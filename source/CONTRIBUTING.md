# Contributing

1. Begin with an owned issue and observable acceptance criteria.
2. Run Issue Planner before implementation.
3. Create a short-lived branch and focused student-authored commits.
4. Run `docker compose exec app pytest` and the documented browser workflow.
5. Open a pull request with evidence and no secrets or personal data.
6. Run Pull Request Reviewer, disposition every finding, and correct valid findings.
7. Merge only after required checks pass, conversations are resolved, evidence is complete, and the rubric/team agreement is met.

Peer review should be substantive when a teammate is available, but there is no mandatory second-person approval gate. Agents cannot approve, merge, deploy, grade, or silently write student work.
